# NBA 경기 시뮬레이터 & 픽 추천 시스템 — 설계 문서 (v1)

- 작성일: 2026-10-22
- 상태: 사용자 검토 대기
- 대상 종목: NBA (KBL·축구는 v2 이후)

---

## 1. 목적과 성공 기준

### 1.1 목적
실제 선수 데이터를 학습해 NBA 경기를 **공격권(possession) 단위로 1만 번 시뮬레이션**하고, 부상·출전 시간·백투백·슛 감각·가비지 타임 같은 **변수 시나리오**를 적용해 승패·핸디캡·언더오버 확률을 계산한다. 이 확률을 **베트맨 프로토 승부식 배당**과 비교해 기대값이 양수인 픽과 2폴더 조합만 추천한다.

### 1.2 사용 방식 (사용자 확정)
1. **매일 자동 리포트**: 예약 작업이 경기 전에 돌아 확률·손익분기표·추천 픽을 만든다.
2. **대시보드**: 경기를 골라 변수를 직접 바꿔 브라우저에서 즉시 다시 시뮬레이션한다.

### 1.3 성공 기준 (v1 완료 판정)
| # | 기준 | 측정 방법 |
|---|---|---|
| S1 | 승률 예측이 기준모델보다 정확 | 2025-26 정규시즌 워크포워드 백테스트에서 Brier score가 '팀 순레이팅 + 홈 어드밴티지' 기준모델보다 낮음 |
| S2 | 확률 보정이 맞음 | 승률 보정 기울기(calibration slope) 0.9~1.1 |
| S3 | 분포 폭이 현실적 | 시뮬레이션 점수 차 표준편차가 실제 잔차 표준편차 ±10% 이내(참고 범위 11.5~13.5점), 총점 표준편차도 ±10% 이내(참고 범위 17~21점) |
| S4 | 자동 리포트가 무인으로 생성 | 시즌 중 매일 07:00 KST 리포트 생성. 데이터 실패 시 '데이터 지연' 표시로 대체 |
| S5 | 대시보드가 빠름 | 변수 하나 변경 후 1만 회 재시뮬레이션이 일반 PC 브라우저에서 5초 이내 |
| S6 | 픽 기록이 남음 | 추천한 모든 픽이 기록되고 결과·적중률·수익률이 자동 집계 |

| 항목 | 내용 |
|---|---|

| 작업 공간 휘발성 | 클라우드 작업 공간은 비활성 시 초기화되고, 예약 작업은 매번 새 세션으로 시작한다. 따라서 코드·데이터·기록은 **대시보드 아티팩트 안에** 보관한다(§12). |
| 과거 배당 부재 | 지난 시즌 베트맨 배당 기록이 없으므로 백테스트는 '확률 정확도'만 검증한다. 수익성은 운영 시작 시점부터 누적 추적한다. |
| 언어 | 전부 JavaScript(ES 모듈). Node 20+와 브라우저에서 같은 엔진 코드를 쓴다. |
| 이용 목적 | 개인·비상업적 분석용. 데이터 요청은 초당 2회 이하, 캐시 우선. |
| 기대치 | 출력은 확률이지 보장이 아니다. 베트맨 2지선다 마켓 마진이 약 13~15%라 좋은 모델이어도 우위는 수 % 수준이다. 베트맨 규정(회차당 1인 구매 한도 등) 준수는 사용자 책임이다. |

## 4. 아키텍처

```
[cdn.nba.com · 부상 리포트 · ESPN]
        │  collect.js (증분 수집, 캐시, 재시도)
        ▼
  원천 데이터 (경기별 박스스코어/플레이바이플레이)
        │  parse.js (공격권·스틴트·슛 구역 분해)
        ▼
  선수-경기 집계 ──► model.js (능력치 + 축소 추정) ──► ratings.json
        │                     minutes.js (출전 시간 계획) ─► minutes.json
        ▼
  sim.js (공격권 몬테카를로) ◄── scenario.js (변수 시나리오)
        │
        ▼  calibrate.js (승률·분포 보정)
  markets.js (승패/승5패/핸디/언오버 확률)
        │                ◄── 베트맨 배당 입력(odds.json)
        ▼
  picks.js (기대값, 단일·2폴더 추천, 손익분기표)
        │
        ├──► report.js → 매일 자동 리포트
        └──► index.html 대시보드 (Web Worker에서 sim.js 실행)
                         └── 픽 기록 DB (아티팩트 DB)
```

### 4.1 모듈과 인터페이스
| 파일 | 책임 | 주요 함수 |
|---|---|---|
| `engine/collect.js` | 외부 데이터 수집 | `fetchSchedule(season)`, `fetchBoxscore(gameId)`, `fetchPlayByPlay(gameId)`, `fetchInjuryReport(dateTimeKST)` |
| `engine/parse.js` | 플레이바이플레이를 공격권·스틴트·슛 구역으로 분해 | `toPossessions(pbp)`, `toStints(pbp, box)`, `shotZone(action)` |
| `engine/model.js` | 선수·팀 능력치 학습 | `buildRatings(playerGames, priors, asOfDate) → Ratings` |
| `engine/minutes.js` | 경기별 출전 시간 계획 | `projectMinutes(teamId, gameDate, ratings, injuries, schedule) → MinutesPlan` |
| `engine/scenario.js` | 변수 시나리오 적용 | `applyScenario(ratings, minutesPlan, scenario) → {ratings, minutesPlan}` |
| `engine/sim.js` | 공격권 시뮬레이션 | `simulateGame(input, {n, seed}) → SimResult` |
| `engine/calibrate.js` | 승률·분포 보정 | `fitCalibration(backtestRows)`, `applyCalibration(simResult, calib)` |
| `engine/markets.js` | 베트맨 마켓별 확률 | `priceMarkets(simResult, lines) → MarketProbs` |
| `engine/picks.js` | 기대값·추천·손익분기표 | `evaluate(marketProbs, odds, rules) → {legs, combos, breakeven}` |
| `engine/report.js` | 리포트 생성 | `renderDailyReport(...) → markdown/html` |
| `jobs/daily.js` | 일일 파이프라인 오케스트레이션(Node) | `runDaily({date})` |
| `jobs/backtest.js` | 워크포워드 백테스트 | `runBacktest({season})` |
| `index.html` | 대시보드 UI | — |
| `test/*.test.js` | 단위·통합 테스트(`node --test`) | — |

### 4.2 핵심 데이터 타입
- **Ratings**: `{asOf, league:{pace, ortg, zoneFg, ...}, teams:{[teamId]:{pace, defZoneMix, defZoneFg, forcedTov, drebPct, homeAdj}}, players:{[playerId]:{teamId, pos, usage, zoneMix:{ra,paint,mid,c3,ab3}, zoneFg:{...}, ftr, ftPct, tov, orebPct, drebPct, astRate, n:{poss, fga3, ...}}}}`
- **MinutesPlan**: `{teamId, players:[{playerId, expMin, playProb, cap?}], rotationByQuarter}`
- **SimResult**: `{gameId, n, seed, winProbHome, margin:{mean, sd, hist[-60..60]}, total:{mean, sd, hist[150..300]}, quantiles, playerMeans}`
- **OddsInput**: §10 참조
- **PickRecord**: §12 참조

| 공식 부상 리포트(PDF) | `https://ak-static.cms.nba.com/referee/injury/Injury-Report_{YYYY-MM-DD}_{시각}.pdf` (파일명의 시각 표기와 갱신 주기는 구현 시 확인) |
| 부상 보조 | `https://site.api.espn.com/apis/site/v2/sports/basketball/nba/injuries` (구현 시 확인) |

- gameId 형식: `002{시즌 앞 두 자리}{5자리 번호}` — 2024-25 = `00224xxxxx`, 2025-26 = `00225xxxxx`, 2026-27 = `00226xxxxx` (정규시즌).

### 5.2 수집 규칙
- 초당 2회 이하, 지수 백오프 재시도(최대 3회), 응답 원본은 압축 저장.
- **증분 수집**: 저장본에 없는 '종료된 경기'만 받는다.
- 첫 구축 시 2024-25(사전값용)와 2025-26(백테스트용), 2026-27(현재) 전 경기를 받는다.
- 부상 리포트는 경기일 기준 가장 최근 PDF를 받아 `{playerName, team, status, reason}`으로 파싱한다. 이름은 박스스코어 선수 목록과 매칭하고, 매칭 실패는 리포트에 표시한다.

## 6. 선수·팀 모델

### 6.1 공격권·스틴트 분해
- 공격권 종료: 야투 성공(앤드원 제외), 수비 리바운드, 턴오버, 마지막 자유투 성공, 쿼터 종료.
- 스틴트: 교체 이벤트로 5인 라인업 구간을 나눈다.
- 검증: 경기별 분해 공격권 수가 박스스코어 기반 추정치(FGA − OREB + TOV + 0.44·FTA)와 ±2% 이내.

### 6.2 선수 능력치 (100공격권 기준)
- 공격 점유율(usage), 슛 구역 분포 5종(제한구역 RA / 페인트 비RA / 중거리 / 코너3 / 정면3)과 구역별 성공률, 자유투 획득률(FTr)과 성공률, 턴오버율, 공격·수비 리바운드율, 어시스트율.
- 슛 구역은 플레이바이플레이의 좌표·구역 필드로 분류하고, 없으면 거리 표기로 분류한다.

### 6.3 축소 추정 (시즌 초 표본 보정)
- `사후값 = (n·관측값 + k·사전값) / (n + k)`
- 사전값: 같은 선수의 지난 시즌 값을 리그 역할군 평균 쪽으로 30% 당긴 값. 신인은 역할군(포지션 × 출전 시간대) 평균.
- k 초기값(교차검증으로 튜닝): 3점 성공률 300시도, RA 성공률 150시도, 중거리 성공률 200시도, 자유투 성공률 100시도, 턴오버율 400공격권, usage 500공격권, 리바운드율 600기회.

### 6.4 팀 수비 (v1은 팀 단위)
- 상대 슛 구역 분포·구역별 허용 성공률(리그 대비, 축소 추정), 유도 턴오버율, 수비 리바운드율, 팀 경기 속도.
- 림 프로텍터 보정: 팀 내 수비 리바운드·블록 상위 빅맨 2명의 출전/결장 시 RA 허용 성공률 차이(강하게 축소).

### 6.5 출전 시간 모델
- 기본값: 최근 15경기 출전 시간의 지수가중평균(반감기 5경기).
- 부상 상태 → 출전 확률(초기값, 백테스트로 보정): Out 0, Doubtful 0.15, Questionable 0.55, Probable 0.9, Available 1.0.
- 결장 시 출전 시간은 같은 포지션 그룹의 뎁스 순서대로 비례 재분배하고, 팀 합계는 240분(연장 시 +25분/연장)으로 맞춘다.
- 백투백 둘째 날: 주전 출전 시간 −8%, 과거 휴식 이력이 있는 선수는 휴식 확률을 부여한다.
- 홈 어드밴티지: 2025-26 데이터로 100공격권당 효율 보정치를 추정한다.

## 7. 시뮬레이터

### 7.1 공격권 루프
1. 현재 시각·점수 차로 양 팀 라인업을 결정한다(출전 시간 계획 + 게임 상황 규칙).
2. 턴오버 여부: 공격 라인업 턴오버율 × 상대 유도 턴오버 보정.
3. 슈터 선택: 코트 위 5명의 usage 비중.
4. 슛 구역 선택: 슈터 구역 분포 × 상대 허용 구역 분포 보정.
5. 성공 여부: 슈터 구역 성공률 × 상대 허용 보정 × **이번 시뮬레이션의 슛 감각 계수**.
6. 슈팅 파울·앤드원 → 자유투. 팀 파울 보너스 자유투 포함.
7. 실패 시 공격 리바운드: 공격 OREB% vs 수비 DREB%로 결정, 성공 시 같은 공격권 연장.
8. 경과 시간: 경기 속도에서 산출한 공격권당 평균 시간 + 잡음.

### 7.2 시뮬레이션마다 뽑는 잠재 변수
- 팀별 슛 감각 계수: 실제 경기 간 3점·2점 성공률 변동과 같은 분산을 갖도록 Beta 분포에서 추출.
- 경기 속도 잡음: N(0, σ), σ는 2025-26 실제 경기 속도 잔차로 추정.

### 7.3 게임 상황 규칙
- **클러치 파울 작전**: 4쿼터 마지막 60초에 3~8점 뒤진 팀은 고의 파울.
- **가비지 타임**: 4쿼터 8분 이하에 20점 이상 차이 또는 4쿼터 중 25점 이상 차이가 나면 양 팀 모두 벤치 라인업으로 전환하고 경기 속도 +3%. (2026-10-22 휴스턴 128-110 사례: 대패 흐름에서 총점이 커지는 현상을 반영)
- 연장: 5분, 같은 규칙.

### 7.4 출력과 성능
- 기본 n = 10,000, 시드 고정으로 재현 가능.
- SimResult(§4.2)와 선수별 평균 기록을 반환한다.
- 성능: 브라우저 Web Worker에서 1만 회 5초 이내, Node 2초 이내.
- 이상치 검사: 점수 차·총점 표준편차가 보정 기준의 ±25%를 벗어나면 해당 경기는 픽을 내지 않고 경고한다.

## 8. 변수 엔진

### 8.1 시나리오 형식
```json
{
  "playerOut": ["1629029"],
  "playProb": {"1630567": 0.5},
  "minutesCap": {"203507": 24},
  "shootingShift": [{"team": "HOU", "fg3": -0.02}],
  "fatigue": [{"team": "DAL", "b2b": true}],
  "chemistry": [{"team": "MIA", "ptsPer100": -1.5}],
  "paceShift": 2,
  "rules": {"garbageTime": true, "clutchFoul": true}
}
```

### 8.2 자동 시나리오 (매일 생성)
- 부상 리포트: Out은 제외, 그 외 상태는 출전 확률로 시뮬레이션마다 출전 여부를 추출.
- 백투백: 일정에서 자동 감지.
- 시즌 초 손발 미숙: 로테이션 상위 8명 중 2명 이상이 새로 합류한 팀은 시즌 1경기 −1.5점/100공격권에서 15경기째 0까지 선형 감소(초기값, 백테스트로 보정).
- 슛 감각의 평균 회귀는 축소 추정(§6.3)으로 자동 반영.

### 8.3 민감도 분석 ("변수 창출")
- 경기마다 주요 변수(주전 각자 결장, 출전 시간 제한 −20%, 슛 감각 ±1σ, 경기 속도 ±3, 백투백 on/off)를 하나씩 바꿔 2,000회씩 재시뮬레이션한다.
- 점수 차 기대값 변화 Top 3와 총점 기대값 변화 Top 3를 따로 정렬해 리포트와 대시보드에 표시한다.

## 9. 마켓 확률과 픽 엔진

### 9.1 마켓 정의 (베트맨 농구)
| 마켓 | 확률 계산 |
|---|---|
| 승패 | P(홈 최종 점수 > 원정) |
| 승5패 | 승: 홈 6점 차 이상 승 / 5: 점수 차 5점 이내 / 패: 원정 6점 차 이상 승 |
| 핸디캡 H(x.5) | 승: 홈 점수 + H > 원정 점수 |
| 언더오버 L(x.5) | 오버: 총점 > L |
| SUM(홀짝) | 제외(구조적으로 기대값 양수가 나오지 않음) |

- 연장 포함 여부는 베트맨 농구 규정을 구현 시 확인하고 그대로 반영한다(기본 가정: 연장 포함).

### 9.2 기대값과 선정 규칙 (사용자 확정)
- 보정 확률 p, 보수 확률 `p_cons = 0.5 + 0.9·(p − 0.5)`.
- 기대값 `EV = p_cons × 배당 − 1`.
- **단일 다리 채택: EV ≥ +3%.**
- **2폴더**: 단일 채택 기준을 통과한 다리 2개로만 구성. 서로 다른 경기, 같은 회차, 원배당 곱(베트맨 표시 반올림 전) **≥ 2.0**. 조합 EV = p₁·p₂·o₁·o₂ − 1 (보수 확률 사용, 서로 다른 경기는 독립으로 가정). 같은 경기 마켓끼리는 조합하지 않는다.
- 정렬: 조합 EV 내림차순, 동률이면 적중 확률이 높은 순. 상위 3개를 가장 이른 마감 시각과 함께 표시.
- **조건을 만족하는 조합이 없으면 "오늘은 패스"를 출력**하고 억지로 만들지 않는다.

### 9.3 손익분기표 (배당 입력 전에도 제공)
- 승패·핸디캡: 각 선택의 최소 필요 배당 `1.03 / p_cons`.
- 언더오버·핸디캡: 예상 기준점 ±3점 구간에서 0.5 단위 기준점별 오버/언더(또는 승/패) 확률과 최소 필요 배당.

## 10. 베트맨 배당 입력

### 10.1 형식
```json
{
  "round": 125,
  "capturedAt": "2026-10-22T14:30:00+09:00",
  "source": "chrome|screenshot|manual",
  "markets": [
    {"betmanNo": 9746, "home": "마이애미 히트", "away": "미네소타 팀버울브스",
     "deadline": "2026-10-22T08:30:00+09:00", "type": "OU", "line": 243.5,
     "odds": {"under": 1.71, "over": 1.77}}
  ]
}
```
- `type`: `ML`(승패) / `ML5`(승5패) / `HC`(핸디캡) / `OU`(언더오버).

### 10.2 입력 경로
1. 사용자가 있을 때 Chrome으로 베트맨 투표지 화면을 읽어 변환(자동 수집 아님).
2. 캡처 이미지 판독.
3. 대시보드 입력 폼.
- 팀명 매핑: 베트맨 한글 팀명 ↔ NBA 3자 약어 매핑표.
- 검증: 배당 1.01~50, 기준점 0.5 단위, 마감 시각이 미래, 회차 일치.

## 11. 출력

### 11.1 대시보드 (아티팩트 웹페이지)
| 탭 | 내용 |
|---|---|
| 오늘 경기 | 경기별 승률, 예상 점수 차·총점, 90% 구간, 데이터 상태 |
| 경기 상세 | 점수 차·총점 분포 차트, 손익분기표, 변수 패널(결장·출전 확률·출전 시간 제한·슛 감각·경기 속도·백투백), 민감도 Top 3, '다시 돌리기'(Web Worker) |
| 배당·픽 | 배당 입력 폼, 기대값 표, 단일·2폴더 추천, "오늘은 패스" 표시 |
| 기록·성적 | 픽 기록, 적중률, 수익률, 예측 EV 대비 실제 성과 |
| 모델 상태 | 마지막 데이터 갱신 시각, 보정 지표(Brier, 보정 기울기, 표준편차 비율) |

- 픽 기능은 백테스트가 성공 기준(S1~S3)을 통과하기 전까지 **비활성**(확률만 표시).

### 11.2 매일 자동 리포트 (예약 작업)
- 시즌 중 매일 **07:00 KST** 실행. 그날 10:00 KST 이후 시작 경기가 있으면 **10:00 KST**에 한 번 더 실행.
- 내용: 경기별 승률·예상 점수 차·예상 총점·90% 구간, 손익분기표, 주요 변수(부상·백투백·민감도 Top 3), 데이터 상태.
- 배당이 들어와 있으면 추천 픽과 2폴더(§9.2)를 포함.
- 전달: 대시보드 갱신 + 요약 알림.

## 12. 저장 (영속성)

대시보드 아티팩트를 프로젝트 저장소로 쓴다.
| 위치 | 내용 |
|---|---|
| 게시 파일 | `index.html`, `engine/*.js`, `jobs/*.js` |
| 게시 데이터 파일(매일 재게시) | `data/ratings_latest.json`, `data/minutes_latest.json`, `data/calibration.json`, `data/schedule.json` |
| 에셋(파일당 15MB 이하) | `player_games_{시즌}.json.gz`, `priors_{시즌}.json.gz`, 백테스트 결과 |
| 아티팩트 DB | `picks`(픽 기록), `results`(결과), `runs`(실행 로그) |

- **PickRecord**: `{id, createdAt, round, betmanNo, gameId, market, selection, line, odds, p, pCons, ev, comboId, stake?, result, settledAt}`
- 일일 작업 순서: 아티팩트 읽기 → 새 경기 증분 수집 → 모델 재학습 → 시뮬레이션 → 데이터 파일 재게시 → 리포트 → 실행 로그 기록 → 전날 픽 결과 정산.

## 14. 테스트·검증

### 14.1 단위 테스트 (`node --test`)
- 공격권 분해 수가 박스스코어 추정치 ±2% 이내.
- 시뮬레이션 불변식: 팀 점수 = 선수 득점 합, 팀 출전 시간 합 = 240분(+연장).
- 리그 평균 두 팀 대결 시 평균 득점·경기 속도가 리그 평균 ±1.5점 이내.
- 같은 시드 → 같은 결과.
- 마켓 계산: 알려진 분포에서 승5패·핸디캡·언더오버 확률이 해석해와 일치.
- 픽 규칙: 같은 경기 조합 금지, 배당 2.0 미만 제외, EV 3% 미만 제외, 조합 없음 → "패스".

### 14.2 워크포워드 백테스트 (2025-26 정규시즌)
- 각 경기일마다 **그 이전 데이터만으로**(사전값은 2024-25) 능력치를 만들고 시뮬레이션한다.
- 지표: 승률 Brier·로그 손실·보정 기울기, 점수 차·총점 MAE와 표준편차 비율.
- 기준모델(팀 순레이팅 + 홈 어드밴티지)과 비교해 S1~S3 판정.
- 보정층(calibrate.js)은 시즌 전반부로 맞추고 후반부로 평가(정보 누출 방지).

### 14.3 실전 추적
- 모든 추천 픽을 기록하고, 적중률·수익률·'예측 EV 대비 실제 결과'를 주간 집계한다.

## 16. 리스크와 한계
- stats.nba.com 클라우드 차단 가능성 → v1은 cdn.nba.com만으로 동작하게 설계.
- cdn.nba.com 응답 형식 변경 → 파서에 스키마 검사와 실패 경고.

- 모델 과신 → 보정층과 실전 추적으로 지속 점검.
