## 1. 목적과 성공 기준

### 1.1 목적
실제 선수 데이터를 학습해 NBA 경기를 **공격권(possession) 단위로 1만 번 시뮬레이션**하고, 부상·출전 시간·백투백·슛 감각·가비지 타임 같은 **변수 시나리오**를 적용해 승패·핸디캡·언더오버 확률을 계산한다. 이 확률을 **베트맨 프로토 승부식 배당**과 비교해 기대값이 양수인 픽과 2폴더 조합만 추천한다.

### 1.2 사용 방식 (사용자 확정)
1. **매일 자동 리포트**: 예약 작업이 경기 전에 돌아 확률·손익분기표·추천 픽을 만든다.
2. **대시보드**: 경기를 골라 변수를 직접 바꿔 브라우저에서 즉시 다시 시뮬레이션한다.

### 1.3 성공 기준 (v1 완료 판정)
| # | 기준 | 측정 방법 |
|---|---|---|
| S1 | 승률 예측이 기준모델보다 정확 | 2025-26 정규시즌 워크포워드 백테스트에서 Brier score가 '팀 순레이팅 + 홈 어드밴티지' 기준모델보다 낮음 |
| S2 | 확률 보정이 맞음 | 승률 보정 기울기(calibration slope) 0.9~1.1 |
| S3 | 분포 폭이 현실적 | 시뮬레이션 점수 차 표준편차가 실제 잔차 표준편차 ±10% 이내, 총점 표준편차도 ±10% 이내. (참고: 처음 적은 범위 11.5~13.5점·17~21점은 실측과 달라 폐기했다. 2024-25 P3 잔차 실측값은 점수 차 14.4점, 판정은 상대 기준으로만 한다.) 세부 판정은 §14.4 |
| S4 | 자동 리포트가 무인으로 생성 | 시즌 중 매일 17:50 ET(06:50 또는 07:50 KST) 리포트 생성. 데이터 실패 시 '데이터 지연' 표시로 대체 |
| S5 | 대시보드가 빠름 | 변수 하나 변경 후 1만 회 재시뮬레이션이 일반 PC 브라우저에서 5초 이내 |
| S6 | 픽 기록이 남음 | 추천한 모든 픽이 기록되고 결과·적중률·수익률이 자동 집계 |

## 2. 범위

### 2.1 v1 포함
- ESPN 기반 데이터 수집(일정, 박스스코어, 플레이바이플레이, 부상), NBA 공식 부상 리포트(보조) 수집
- 선수 능력치 모델(시즌 초 축소 추정 포함), 팀 수비 보정(팀 단위), 출전 시간 모델
- 공격권 단위 몬테카를로 시뮬레이터 + 확률 보정층
- 변수 엔진: 결장, 출전 확률, 출전 시간 제한, 백투백, 시즌 초 손발 미숙, 슛 감각 변동, 가비지 타임, 클러치 파울 작전
- 민감도 분석("이 경기를 가장 크게 흔드는 변수 Top 3")
- 픽 엔진(기대값 계산, 단일/2폴더 추천, 손익분기표)
- 베트맨 배당 입력(Chrome 화면 판독 / 캡처 판독 / 수동 입력)
- 대시보드(아티팩트 웹페이지), 매일 자동 리포트(예약 작업), 픽 기록·성적 집계
- 2025-26 시즌 워크포워드 백테스트

### 2.2 v2 이후로 미룸
- 회귀분석 기반 개인 수비 영향력(RAPM), stats.nba.com 라인업·트래킹 데이터
- 이동 거리·시차·고지대(덴버/유타) 효과, 심판 성향
- 해외 배당 비교(유료 API 키 필요), KBL·축구 확장

## 4. 아키텍처

```
[ESPN (일정·경기·부상) · NBA 부상 리포트 PDF(보조)]
        │  collect.js (증분 수집, 캐시, 재시도)
        ▼
  원천 데이터 (경기별 박스스코어/플레이바이플레이)
        │  parse.js (공격권·스틴트·슛 구역 분해)
        ▼
  선수-경기 집계 ──► model.js (능력치 + 축소 추정) ──► ratings.json
        │                     minutes.js (출전 시간 계획) ─► minutes.json
        ▼
  sim.js (공격권 몬테카를로) ◄── scenario.js (변수 시나리오)
        │
        ▼  calibrate.js (승률·분포 보정)
  markets.js (승패/승5패/핸디/언오버 확률)
        │                ◄── 베트맨 배당 입력(odds.json)
        ▼
  picks.js (기대값, 단일·2폴더 추천, 손익분기표)
        │
        ├──► report.js → 매일 자동 리포트
        └──► index.html 대시보드 (Web Worker에서 sim.js 실행)
                         └── 픽 기록 DB (아티팩트 DB)
```

### 4.1 모듈과 인터페이스
| 파일 | 책임 | 주요 함수 |
|---|---|---|
| `engine/collect.js` | 외부 데이터 수집 | `fetchSchedule(season)`, `fetchBoxscore(gameId)`, `fetchPlayByPlay(gameId)`, `fetchInjuryReport(dateTimeKST)` |
| `engine/parse.js` | 플레이바이플레이를 공격권·스틴트·슛 구역으로 분해 | `toPossessions(pbp)`, `toStints(pbp, box)`, `shotZone(action)` |
| `engine/model.js` | 선수·팀 능력치 학습 | `buildRatings(playerGames, priors, asOfDate) → Ratings` |
| `engine/minutes.js` | 경기별 출전 시간 계획 | `projectMinutes(teamId, gameDate, ratings, injuries, schedule) → MinutesPlan` |
| `engine/scenario.js` | 변수 시나리오 적용 | `applyScenario(ratings, minutesPlan, scenario) → {ratings, minutesPlan}` |
| `engine/sim.js` | 공격권 시뮬레이션 | `simulateGame(input, {n, seed}) → SimResult` |
| `engine/calibrate.js` | 승률·분포 보정 | `fitCalibration(backtestRows)`, `applyCalibration(simResult, calib)` |
| `engine/markets.js` | 베트맨 마켓별 확률 | `priceMarkets(simResult, lines) → MarketProbs` |
| `engine/picks.js` | 기대값·추천·손익분기표 | `evaluate(marketProbs, odds, rules) → {legs, combos, breakeven}` |
| `engine/report.js` | 리포트 생성 | `renderDailyReport(...) → markdown/html` |
| `jobs/daily.js` | 일일 파이프라인 오케스트레이션(Node) | `runDaily({date})` |
| `jobs/backtest.js` | 워크포워드 백테스트 | `runBacktest({season})` |
| `index.html` | 대시보드 UI | — |
| `test/*.test.js` | 단위·통합 테스트(`node --test`) | — |

### 4.2 핵심 데이터 타입
- **Ratings**: `{asOf, league:{pace, ortg, zoneFg, ...}, teams:{[teamId]:{pace, defZoneMix, defZoneFg, forcedTov, drebPct, homeAdj}}, players:{[playerId]:{teamId, pos, usage, zoneMix:{ra,paint,mid,c3,ab3}, zoneFg:{...}, ftr, ftPct, tov, orebPct, drebPct, astRate, n:{poss, fga3, ...}}}}`
- **MinutesPlan**: `{teamId, players:[{playerId, expMin, playProb, cap?}], rotationByQuarter}`
- **SimResult**: `{gameId, n, seed, winProbHome, margin:{mean, sd, hist[-60..60]}, total:{mean, sd, hist[150..300]}, quantiles, playerMeans}`
- **OddsInput**: §10 참조
- **PickRecord**: §12 참조

## 5. 데이터 수집

### 5.1 원천 (2026-10-22 개정: 주 출처 ESPN. 실제 응답 확인 결과는 `docs/schemas/p0-results.md`)
| 데이터 | 출처 | URL 패턴 |
|---|---|---|
| 일정·스코어보드 | ESPN (주) | `https://site.api.espn.com/apis/site/v2/sports/basketball/nba/scoreboard?dates=YYYYMMDD` (날짜별 조회. 기간 조회는 0건을 돌려줌) |
| 박스스코어 + 플레이바이플레이 | ESPN (주) | `https://site.api.espn.com/apis/site/v2/sports/basketball/nba/summary?event={espnId}` |
| 부상 | ESPN (주) | `https://site.api.espn.com/apis/site/v2/sports/basketball/nba/injuries` (상태는 `Out` / `Day-To-Day` 두 가지) |
| 공식 부상 리포트(PDF) | NBA (보조) | `https://ak-static.cms.nba.com/referee/injury/Injury-Report_{YYYY-MM-DD}_{hh}_{mm}{AM\|PM}.pdf` (**2025-12-22부터** 15분 간격, 미국 동부시간 기준. 2025-12-21까지는 `_{hh}{AM\|PM}` 시간 단위 형식. P1에서 확인) |
| ~~cdn.nba.com 일정·박스·PBP~~ | 사용 불가 | 클라우드에서 IP 차단(§3). 수집기는 어댑터 구조로 만들어, 차단이 풀리면 붙일 수 있게만 둔다. |

- 경기 ID: ESPN 이벤트 ID(예: `401809234`)를 쓴다. 정규시즌 판별은 `season.slug == "regular-season"`(`season.type == 2`)로 한다. `season.year`는 시즌이 끝나는 해다(2025-26 → 2026).
- 팀 약어는 ESPN 표기를 기준으로 한다(예: `WSH`, `GS`, `SA`, `NY`, `NO`, `UTAH`). NBA PDF의 표기(확인된 예: `MIL@WAS`)는 매핑표로 변환한다. 30개 팀 ESPN 약어는 P0 샘플에서 전부 확인했다.
- 박스스코어 출전 시간(MIN)은 정수 분이다. 정밀한 출전 시간은 교체 이벤트로 계산한다.
- ESPN 박스스코어의 공격 리바운드(OREB)는 팀 리바운드를 포함하지 않는다(플레이바이플레이에는 "team rebound"로 있음).

### 5.2 수집 규칙
- 초당 2회 이하, 지수 백오프 재시도(최대 3회), 응답 원본은 압축 저장.
- **증분 수집**: 저장본에 없는 '종료된 경기'만 받는다.
- 첫 구축 시 2024-25(사전값용)와 2025-26(백테스트용), 2026-27(현재) 전 경기를 받는다.
- 부상은 ESPN injuries를 주 출처로 쓴다. 보조로 경기일 기준 가장 최근 NBA PDF를 받아 `{playerName, team, status, reason}`으로 파싱한다. PDF는 형식 검사(머리글 열 `Game Date, Game Time, Matchup, Team, Player Name, Current Status, Reason`)를 통과할 때만 쓴다. PDF에만 있는 세분 상태(Questionable/Doubtful/Probable)의 반영 방식은 계획 문서의 결정을 따른다. 이름은 박스스코어 선수 목록과 매칭하고, 매칭 실패는 리포트에 표시한다.
- **데이터 결함 처리 규칙(P1 확정, 상세 `docs/reports/p1-report.md` §4)**
  - 플레이바이플레이가 최종 점수와 안 맞는 경기(`pbp_incomplete`)는 플레이바이플레이 파생 데이터를 모두 제외한다.
  - 깨진 박스 TOV는 플레이바이플레이 값으로 대체한다.
  - 들어온 선수가 빠진 교체는 그 선수의 이후 행동으로 소급 복구한다. 복구 못 한 구간은 라인업 기능에서 제외한다.
  - 팀 출전 시간 합이 1분 넘게 틀린 경기는 스틴트를 쓰지 않고 박스 MIN을 쓴다.
  - "Heave Jump Shot"(2025-26부터 박스 FGA에서 제외됨)은 야투·구역·성공률에서 빼고 공격권 종료로만 센다.
  - NBA 부상 PDF 파일명은 2025-12-21까지 `_{hh}{AM|PM}`(시간 단위), 2025-12-22부터 `_{hh}_{mm}{AM|PM}`(15분 단위)다.
- **스키마 검증**: 모든 ESPN 응답은 `engine/schema/espn.js`로 검사한다. 형식이 어긋나면(필드 누락·타입 변경·박스 레이블 변경·처음 보는 플레이 유형 등) 실패로 처리하고 수집을 중단하며, 이유를 리포트에 남긴다. 형식은 맞지만 데이터가 깨진 경우(음수 팀 턴오버, 들어온 선수가 빠진 교체 등)는 해당 경기에 품질 경고를 붙이고 대체 규칙으로 처리하며, 경고 목록을 리포트에 표시한다.

## 6. 선수·팀 모델

### 6.1 공격권·스틴트 분해
- 공격권 종료: 야투 성공(앤드원 제외), 수비 리바운드, 턴오버, 마지막 자유투 성공, 쿼터 종료.
- 스틴트: 교체 이벤트로 5인 라인업 구간을 나눈다.
- 검증 (2026-10-22 개정, 사용자 결정): 기준 추정치는 **보정식** `FGA − (OREB + 팀 공격 리바운드) + TOV + 0.44·FTA`다.
  - 팀 공격 리바운드는 플레이바이플레이에서 세고, 자유투 사이 데드볼 리바운드는 제외한다.
  - 박스 TOV가 깨졌으면(0 또는 음수인데 플레이바이플레이에 턴오버가 있음) 플레이바이플레이 TOV를 쓴다.
  - 합격선
    1. 경기별 오차(분해 공격권 수 대비 추정치)의 평균 절댓값 ≤ 2%
    2. 최대 절댓값 ≤ 3.5%
    3. 같은 경기 홈·원정 분해 공격권 수 차이 ≤ 2
  - **전 경기 기준(P2, 2026-10-22 사용자 결정)**
    - 수집한 전 경기(플레이바이플레이 정상 경기)에 대해 경기별 |오차| **평균 ≤ 2%**, **95번째 백분위 ≤ 3.5%**를 요구한다.
    - 3.5%를 넘는 경기는 목록과 원인을 붙여 보고한다(`docs/reports/p2-report.md`).
    - 경기별 검사(공격권, heave 규칙 대조, 팀 출전 시간 합, 플레이바이플레이 끊김)는 수집 때 자동으로 돌려 `data/checks/{season}.json`에 남긴다.
    - 제외 경기는 `data/excluded_games.json`에 이유와 함께 남긴다.
    - 시즌별 제외 비율이 5%를 넘으면 수집을 멈추고 보고한다.
  - 개정 이유: P0(20경기)에서 ESPN 박스스코어의 OREB에 팀 리바운드가 빠져 있음을 확인했다(팀·경기당 3~5개). 그래서 원식은 공격권을 구조적으로 많게 추정한다(원식 대비 평균 −1.65%, ±2% 통과 7/20). 박스 TOV가 깨진 경기도 있었다(2026-01-21 LAC@CHI, 13.15% 이탈). 원식의 경기별 ±2%는 추정식 자체의 경기별 오차 때문에 정상 분해도 넘을 수 있다. 그래서 평균 ≤ 2%와 최대 ≤ 3.5%로 나눴고, 분해 자체의 일관성은 홈·원정 차이(공격권은 번갈아 오가므로 크게 벌어질 수 없음)로 따로 검사한다.

### 6.2 선수 능력치 (100공격권 기준)
- 공격 점유율(usage), 슛 구역 분포 5종(제한구역 RA / 페인트 비RA / 중거리 / 코너3 / 정면3)과 구역별 성공률, 자유투 획득률(FTr)과 성공률, 턴오버율, 공격·수비 리바운드율, 어시스트율.
- 슛 구역은 플레이바이플레이의 좌표·구역 필드로 분류하고, 없으면 거리 표기로 분류한다.

### 6.3 축소 추정 (시즌 초 표본 보정)
- `사후값 = (n·관측값 + k·사전값) / (n + k)`
- 사전값: 같은 선수의 지난 시즌 값을 리그 역할군 평균 쪽으로 30% 당긴 값. 신인은 역할군(포지션 × 출전 시간대) 평균.
- k 초기값(교차검증으로 튜닝): 3점 성공률 300시도, RA 성공률 150시도, 중거리 성공률 200시도, 자유투 성공률 100시도, 턴오버율 400공격권, usage 500공격권, 리바운드율 600기회.

### 6.4 팀 수비 (v1은 팀 단위)
- 상대 슛 구역 분포·구역별 허용 성공률(리그 대비, 축소 추정), 유도 턴오버율, 수비 리바운드율, 팀 경기 속도.
- 림 프로텍터 보정: 팀 내 수비 리바운드·블록 상위 빅맨 2명의 출전/결장 시 RA 허용 성공률 차이(강하게 축소).

### 6.5 출전 시간 모델
- 기본값: 최근 15경기 출전 시간의 지수가중평균(반감기 5경기).
- 부상 상태 → 출전 확률: 초기값 Out 0, Doubtful 0.15, Questionable 0.55, Probable 0.9, Available 1.0 → **2026-10-22 2024-25 경기 전 스냅샷으로 보정: Doubtful 0.02, Questionable 0.53, Probable 0.97**(로테이션 선수 실제 출전 비율, `data/model/play-prob.json`). Out 0·Available 1·ESPN Day-To-Day 0.55는 유지.
- 운영 시 상태 결정(2026-10-22 사용자 결정)
  - ESPN `Out`은 0이다.
  - ESPN `Day-To-Day`는 같은 날 NBA PDF가 형식 검사를 통과하면 PDF의 상태(Doubtful/Questionable/Probable)를 쓴다. 없으면 0.55다.
  - ESPN에 없고 PDF에만 있는 선수는 PDF 상태를 쓴다.
- 결장 시 출전 시간은 같은 포지션 그룹의 뎁스 순서대로 비례 재분배하고, 팀 합계는 240분(연장 시 +25분/연장)으로 맞춘다.
- 백투백 둘째 날: 주전 출전 시간 −8%, 과거 휴식 이력이 있는 선수는 휴식 확률을 부여한다.
- 홈 어드밴티지: 100공격권당 효율 보정치를 **그 날짜 이전 경기만으로**(워크포워드, 축소 k=300) 추정한다. (원래 문구 "2025-26 데이터로 추정"은 시험 시즌을 쓰게 되므로 2026-10-22 누출 점검 F9에 따라 고쳤다. 구현은 처음부터 워크포워드였다.)

## 7. 시뮬레이터

### 7.1 공격권 루프
1. 현재 시각·점수 차로 양 팀 라인업을 결정한다(출전 시간 계획 + 게임 상황 규칙).
2. 턴오버 여부: 공격 라인업 턴오버율 × 상대 유도 턴오버 보정.
3. 슈터 선택: 코트 위 5명의 usage 비중.
4. 슛 구역 선택: 슈터 구역 분포 × 상대 허용 구역 분포 보정.
5. 성공 여부: 슈터 구역 성공률 × 상대 허용 보정 × **이번 시뮬레이션의 슛 감각 계수**.
6. 슈팅 파울·앤드원 → 자유투. 팀 파울 보너스 자유투 포함.
7. 실패 시 공격 리바운드: 공격 OREB% vs 수비 DREB%로 결정, 성공 시 같은 공격권 연장.
8. 경과 시간: 경기 속도에서 산출한 공격권당 평균 시간 + 잡음.

### 7.2 시뮬레이션마다 뽑는 잠재 변수
- 팀별 슛 감각 계수: 실제 경기 간 3점·2점 성공률 변동과 같은 분산을 갖도록 Beta 분포에서 추출.
- 경기 속도 잡음: N(0, σ), σ는 2025-26 실제 경기 속도 잔차로 추정.

> **2026-10-22 P4 변경 — 사용자 승인(2026-10-22), 근거 `docs/reports/p4-report.md`, 튜닝 장부에 기록(1단계 24회, 2단계 10회, 진단 9회)**
> - 원래 설계대로면 시뮬레이션 점수 차 표준편차가 16.5점이다. 실제 잔차 표준편차는 14.3점이라 P4 기준(±10%)을 넘는다. 공격권을 서로 독립으로 두면 실제 경기에 있는 점수 효과(앞선 팀이 느슨해짐)가 빠지기 때문이다. 그래서 아래처럼 바꿨다. 값은 모두 2024-25에서만 정했고 튜닝 장부에 누적했다.
> - **점수 효과 `kappa`(추가):** 앞선 점수 차가 그 시점의 기대 점수 차보다 1점 클 때마다 공격 팀 성공률을 kappa% 낮춘다(뒤진 팀은 같은 만큼 높인다). 기대 점수 차를 기준으로 하므로 평균 점수 차는 바뀌지 않는다. **선택값 0.2**
> - **정규시간 경기 속도 계수 `regPace`(추가):** P3 레이팅에는 실제 경기의 막판 파울과 연장 득점이 이미 들어 있다. 규칙(§7.3)을 켜면 이 효과가 두 번 들어가 총점이 +1.9점 높아진다. 그래서 정규시간 공격권 수에 계수를 곱해 규칙을 켠 평균 총점을 P3 직접 예측과 맞춘다. **선택값 0.9917**
> - **팀 슛 감각 계수 → 0:** 슛마다의 확률 잡음만으로 경기 간 변동이 이미 실제 잔차 수준이다. 감각 계수를 더하면 분산이 기준을 넘는다(그리드 결과).
> - **경기 속도 잡음 σ → 2024-25로 추정, 선택값 0:** 2025-26은 봉인된 시험 시즌이라 쓸 수 없다. 공격권 시간의 무작위성만으로 총점 분산이 맞았다.
> - 공유 슈팅 환경 `gameSD`(양 팀 공통 계수)도 시험했지만 총점 분산만 키워 0으로 두었다.

### 7.3 게임 상황 규칙
- **클러치 파울 작전**: 4쿼터 마지막 60초에 3~8점 뒤진 팀은 고의 파울.
- **가비지 타임**: 4쿼터 8분 이하에 20점 이상 차이 또는 4쿼터 중 25점 이상 차이가 나면 양 팀 모두 벤치 라인업으로 전환하고 경기 속도 +3%. (2026-10-22 휴스턴 128-110 사례: 대패 흐름에서 총점이 커지는 현상을 반영)
- 연장: 5분, 같은 규칙.

### 7.4 출력과 성능
- 기본 n = 10,000, 시드 고정으로 재현 가능.
- SimResult(§4.2)와 선수별 평균 기록을 반환한다.
- 성능: 브라우저 Web Worker에서 1만 회 5초 이내, Node 2초 이내.
- 이상치 검사: 점수 차·총점 표준편차가 보정 기준의 ±25%를 벗어나면 해당 경기는 픽을 내지 않고 경고한다.

### 8.1 시나리오 형식

### 8.2 자동 시나리오 (매일 생성)
- 부상 리포트: Out은 제외, 그 외 상태는 출전 확률로 시뮬레이션마다 출전 여부를 추출.
- 백투백: 일정에서 자동 감지.
- 시즌 초 손발 미숙: 로테이션 상위 8명 중 2명 이상이 새로 합류한 팀은 시즌 1경기 −1.5점/100공격권에서 15경기째 0까지 선형 감소(초기값, 백테스트로 보정).
- 슛 감각의 평균 회귀는 축소 추정(§6.3)으로 자동 반영.

### 8.3 민감도 분석 ("변수 창출")
- 경기마다 주요 변수(주전 각자 결장, 출전 시간 제한 −20%, 슛 감각 ±1σ, 경기 속도 ±3, 백투백 on/off)를 하나씩 바꿔 2,000회씩 재시뮬레이션한다.
- 점수 차 기대값 변화 Top 3와 총점 기대값 변화 Top 3를 따로 정렬해 리포트와 대시보드에 표시한다.

### 8.4 시나리오와 앙상블의 결합 (2026-10-22 사용자 결정 4)
- 기준 위치: 앙상블 점수 차 = w·(기준 시뮬레이션 평균) + (1 − w)·(단순 기준모델 점수 차). w는 2024-25로 정한 가중치 1개다(`data/model/calibration.json`).
- 시나리오를 적용하면 **"시나리오 시뮬레이션 − 기준 시뮬레이션" 변화량을 앙상블 기준 위치에 더한다.**
  - 구현: 시나리오 시뮬레이션의 점수 차 분포 전체를 기준 시뮬레이션과 같은 이동량(앙상블 − 기준 시뮬레이션 평균)만큼 옮긴다.
  - 그러면 평균은 "앙상블 + 시나리오 변화량"이 되고, 분포 모양 변화(결장으로 분산이 커지는 등)도 그대로 남는다.
- 최종 확률만 섞지 않는다. 시나리오 효과가 앙상블 때문에 희석되거나 사라지면 안 된다.
- 총점은 앙상블하지 않는다(시뮬레이션 그대로). 단순 기준모델의 총점은 비교용이다.

## 9. 마켓 확률과 픽 엔진

### 9.1 마켓 정의 (베트맨 농구)
| 마켓 | 확률 계산 |
|---|---|
| 승패 | P(홈 최종 점수 > 원정) |
| 승5패 | 승: 홈 6점 차 이상 승 / 5: 점수 차 5점 이내 / 패: 원정 6점 차 이상 승 |
| 핸디캡 H(x.5) | 승: 홈 점수 + H > 원정 점수 |
| 언더오버 L(x.5) | 오버: 총점 > L |
| SUM(홀짝) | 제외(구조적으로 기대값 양수가 나오지 않음) |

- 연장 포함 여부는 베트맨 농구 규정을 구현 시 확인하고 그대로 반영한다(기본 가정: 연장 포함).

### 9.2 기대값과 선정 규칙 (사용자 확정)
- 보정 확률 p, 보수 확률 **`p_cons = p − 0.1·|p − 0.5|`** (2026-10-22 사용자 승인으로 교체. 고른 쪽 확률을 항상 낮춘다).
  - 비교를 위해 기존 공식 값 `p_cons_old = 0.5 + 0.9·(p − 0.5)`도 픽 기록에 함께 남긴다. 채택 판단은 새 공식으로만 한다.
- 기대값 `EV = p_cons × 배당 − 1`.
- **단일 다리 채택: EV ≥ +3%.**
- **2폴더**: 단일 채택 기준을 통과한 다리 2개로만 구성. 서로 다른 경기, 같은 회차, 원배당 곱(베트맨 표시 반올림 전) **≥ 2.0**. 조합 EV = p₁·p₂·o₁·o₂ − 1 (보수 확률 사용, 서로 다른 경기는 독립으로 가정). 같은 경기 마켓끼리는 조합하지 않는다.
- 정렬: 조합 EV 내림차순, 동률이면 적중 확률이 높은 순. 상위 3개를 가장 이른 마감 시각과 함께 표시.
- **조건을 만족하는 조합이 없으면 "오늘은 패스"를 출력**하고 억지로 만들지 않는다.

### 9.3 손익분기표 (배당 입력 전에도 제공)
- 승패·핸디캡: 각 선택의 최소 필요 배당 `1.03 / p_cons`.
- 언더오버·핸디캡: 예상 기준점 ±3점 구간에서 0.5 단위 기준점별 오버/언더(또는 승/패) 확률과 최소 필요 배당.

### 9.4 기록 전용 기간 (2026-10-22 추가, 사용자 조건)
- **한계:** 과거 베트맨 배당 기록이 없다. 그래서 백테스트(S1~S3)는 확률이 정확하고 잘 보정됐는지만 보여 줄 수 있고, **배당 대비 이익(기대값이 실제로 양수인지)은 증명하지 못한다**(§3 "과거 배당 부재"). 베트맨 마진(약 13~15%)을 넘는 우위가 있는지는 실제 배당이 쌓여야 판단할 수 있다.
- **기록 전용 기간:** 픽 기능이 S1~S3 통과로 켜진 뒤에도 바로 돈을 걸지 않는다. 처음에는 "기록만 하는" 기간으로 운영한다.
  - 추천 픽과 2폴더를 지금과 같은 규칙(§9.2)으로 계산해 보여 준다. 화면과 리포트에는 **"기록 전용 — 구매 비권장"**을 표시한다.
  - 모든 추천을 입력한 실제 배당과 함께 픽 기록 DB에 남기고(§12 PickRecord, `stake` 비움), 결과를 자동 정산한다.
  - 주간 집계 항목(§14.3)
    - 적중률과 예측 보수 확률 `p_cons`의 차이(보정)
    - 1단위 균등 가정 수익률과 95% 구간
    - 예측 EV 대비 실현 결과
- **종료 조건 (2026-10-22 사용자 확정)**
  - 아래를 **모두** 충족하면 결과를 보고한다. 해제는 **사용자 승인으로만** 한다.
    1. 실제 베트맨 배당으로 기록한 단일 픽 **200개 이상**, 기간 **8주 이상**
    2. 보정: 예측 확률(`p_cons`) 평균과 실제 적중률의 차이 **±5%p 이내**
    3. 시장 대비 정확도: 같은 경기들에서 모델 확률의 Brier 점수가 **시장 내재확률(마진 제거)의 Brier 점수보다 나쁘지 않을 것**
       - 시장 내재확률 = (1/배당) ÷ Σ(1/배당). 같은 마켓의 모든 선택지 배당을 기록해야 한다(§10 입력 형식에 이미 포함).
       - 비교 대상은 모든 기록 경기 마켓이다(픽으로 고른 것만이 아님).
    4. 수익률(1단위 균등): **점추정 ≥ 0** 그리고 **95% 구간 하한 ≥ −10%**
  - 해제 후 **첫 4주는 최소 금액**으로만 운영하고, 같은 지표를 계속 집계한다.
  - 2폴더는 따로 집계해 같은 조건으로 판단한다.
- **주당 예상 픽 수:** 200개에 걸리는 기간을 가늠하기 위한 추정이다. §9.5에 적고, P5 백테스트 뒤 갱신한다.
- 구현: P9(일일 작업)과 P8(대시보드)에 `mode: "record-only"` 플래그를 둔다. 기본값은 켜짐이고, 해제는 사용자 승인 기록이 있을 때만 가능하다.

### 9.5 주당 예상 픽 수 (2026-10-22 추정, P5 백테스트 뒤 갱신)
- **전제와 한계:** 과거 베트맨 배당이 없어서, 시장 확률을 가정해 계산한 추정이다.
  - 대상: 승패 마켓 단일 다리만(핸디캡·언오버는 기준점 정보가 없어 제외)
  - 기간: 2024-25 정규시즌 전체(24.7주, 1,230경기). P3 해석 모델(실제 출전자 판)과 2024-25에서 맞춘 σ를 썼다.
  - 배당 = 1 ÷ (시장 확률 × 오버라운드). 오버라운드는 1.13~1.15, 비례 배분이다.
  - 채택 기준은 §9.2와 같다(EV ≥ +3%).

| 시장 확률 가정 | 보수 확률 `p_cons` 공식 | 주당 픽 | 200개까지 | 채택 픽 적중률 |
|---|---|---|---|---|
| 시장 = 단순 기준모델(팀 순레이팅+홈) — 낙관적 | 설계 공식 0.5+0.9(p−0.5) | 18.3~19.9 | 10~11주 | 36~37% |
| 〃 | 하향 공식 p−0.1·\|p−0.5\| (제안) | 13.4~15.2 | 13~15주 | 39~41% |
| 시장 = 우리 모델과 같은 정확도 — 우위 없음 | 설계 공식 | 2.7~3.4 | 60~75주 | **6~11%** |
| 〃 | 하향 공식 | **0** | — | — |

- **해석**
  - 실제 시장은 단순 기준모델보다 정확하다고 보는 게 합리적이다. 그래서 실제 주당 픽 수는 0과 첫 행(약 15~20개) 사이 어딘가다.
  - 200개를 모으는 데 **최소 10주 이상, 우위가 작으면 한 시즌 안에 못 모을 수 있다.**
  - 첫 실측(기록 전용 4주) 뒤 이 표를 실제 배당으로 갱신한다.
- **보수 확률 공식의 결함(사용자 결정 필요, P4 보고)**
  - 설계 공식 `p_cons = 0.5 + 0.9(p − 0.5)`은 확률을 0.5 쪽으로 당긴다.
  - 그래서 **언더독의 확률을 오히려 높인다**(p=0.05 → 0.095).
  - "시장 = 우리 모델"(우위 없음) 가정에서도 큰 언더독에 가짜 기대값이 생겨, 주 3개 안팎의 픽이 나오고 적중률은 6~11%다.
  - 제안: 고른 쪽의 확률을 항상 낮추는 `p_cons = p − 0.1·|p − 0.5|`
    - p > 0.5에서는 설계 공식과 같다.
    - p < 0.5에서는 더 낮춘다.
    - 우위가 없으면 픽이 0개가 된다.
  - **2026-10-22 사용자 승인으로 교체했다(§9.2).** 기존 공식 값은 기록에만 남긴다.

3. 대시보드 입력 폼.
- 팀명 매핑: 베트맨 한글 팀명 ↔ NBA 3자 약어 매핑표.
- 검증: 배당 1.01~50, 기준점 0.5 단위, 마감 시각이 미래, 회차 일치.

## 11. 출력

### 11.1 대시보드 (아티팩트 웹페이지)
| 탭 | 내용 |
|---|---|
| 오늘 경기 | 경기별 승률, 예상 점수 차·총점, 90% 구간, 데이터 상태 |
| 경기 상세 | 점수 차·총점 분포 차트, 손익분기표, 변수 패널(결장·출전 확률·출전 시간 제한·슛 감각·경기 속도·백투백), 민감도 Top 3, '다시 돌리기'(Web Worker) |
| 배당·픽 | 배당 입력 폼, 기대값 표, 단일·2폴더 추천, "오늘은 패스" 표시 |
| 기록·성적 | 픽 기록, 적중률, 수익률, 예측 EV 대비 실제 성과 |

- 픽 기능은 백테스트가 성공 기준(S1~S3)을 통과하기 전까지 **비활성**(확률만 표시).

### 11.2 매일 자동 리포트 (예약 작업)
- **예약은 미 동부 시각(America/New_York) 기준이다** (2026-10-22 사용자 결정, P2 조건 7)
  - 실행 A: 매일 **17:50 ET**. `CRON_TZ=America/New_York 50 17 * * *`
  - 실행 B: 매일 **20:50 ET**. 21:00 ET 이후 시작 경기가 그날 없으면 즉시 종료한다. `CRON_TZ=America/New_York 50 20 * * *`
  - 이유: 한국 시각으로 고정하면, 2026-11-01 서머타임 종료 뒤 06:50 KST가 16:50 ET로 당겨진다. 그러면 부상 PDF 스냅샷 시점이 백테스트 (B)의 17:50 ET와 어긋나고, 경기 직전 정보도 1시간 오래된다.
  - 한국 시각으로 보면 다음과 같다.

    | 기간 | 실행 A | 실행 B |
    |---|---|---|
    | 서머타임 중(~2026-10-31, 2027-03-14~) | 06:50 KST | 09:50 KST |
    | 표준시(2026-11-01 ~ 2027-03-13) | 07:50 KST | 10:50 KST |

  - 백테스트 (B)의 부상 스냅샷 기준(17:50 ET 이전 마지막 PDF)과 운영 실행 A의 시각이 같다.
- 내용: 경기별 승률·예상 점수 차·예상 총점·90% 구간, 손익분기표, 주요 변수(부상·백투백·민감도 Top 3), 데이터 상태.
- 배당이 들어와 있으면 추천 픽과 2폴더(§9.2)를 포함.
- 전달: 대시보드 갱신 + 요약 알림.

### 14.1 단위 테스트 (`node --test`)
- 공격권 분해: §6.1 개정 기준(보정 추정식 대비 평균 |오차| ≤ 2%, 최대 ≤ 3.5%, 홈·원정 차이 ≤ 2).

### 14.2 워크포워드 백테스트 (2025-26 정규시즌)

- **두 판으로 돌려 둘 다 보고한다** (2026-10-22 사용자 결정)
  - (A) 실제 출전자 판: 그 경기에 실제로 뛴 선수(박스스코어)로 출전 계획을 세운다. 부상 정보 오차를 뺀 모델 자체의 상한 성능이다.
  - (B) 경기 전 스냅샷 판: **경기일 17:50 ET 이전에 올라온 마지막 NBA 부상 PDF**(운영 실행 A와 같은 시각)만 쓴다(P2 사용자 결정). 17:50 ET보다 먼저 시작하는 경기는 정보 누출을 막기 위해 시작 시각 이전 마지막 PDF를 쓴다. Out은 제외하고, 나머지는 §6.5 출전 확률로 처리한다.
    - ESPN 부상 피드는 과거 시점 조회가 안 된다. 그래서 백테스트는 PDF 스냅샷만으로 한다.
    - 이 판은 운영 때 정보 조건을 재현한다.
- 기준모델(팀 순레이팅 + 홈 어드밴티지)과 비교해 S1~S3을 판정한다. **픽 활성화 판단은 (B) 기준으로 한다.**
- **경기 그룹과 보고 구간(P2 마무리 결정, 2026-10-22)**
  - 그룹(`engine/snapshot.js`): A(17:50 ET 실행, 21:00 ET 전 시작), B(20:50 ET 실행, 21:00 ET 이후 시작, 20:50 ET 이전 마지막 PDF), `pre_job_start`(17:50 ET 이전 시작, 시작 전 마지막 PDF)
  - **`pre_job_start`는 S1~S3 판정에서 제외하고 참고로만 보고한다.**
  - 결과는 2025-12-21 이전(시간 단위 PDF)과 2025-12-22 이후(15분 단위 PDF)로 나눠 보고하고, 각 구간 안에서 A·B를 따로 보인다.
- **데이터 분할(P3 사용자 결정, 2026-10-22)**
  - 2024-25: **개발 시즌**. 모든 하이퍼파라미터(수축 강도, 반감기, 경기 속도 수축, 승률 σ)와 보정층(calibrate.js)은 2024-25 전진 평가로만 정한다.

  - 2026-27: **누적 검증용**. 시즌이 진행되며 쌓이는 경기로 계속 확인한다.

  - 판정은 **(B) 경기 전 스냅샷 판**으로 한다. (A)는 참고로 함께 보고한다.
- **합격 기준(세 가지 모두)**
  - **S1:** 모델 승률(보정층 적용 후)의 Brier가 기준모델(팀 순레이팅 + 홈 이점, 설계 기본값 고정)의 Brier보다 **낮다**(점추정). 차이의 부트스트랩 95% 구간도 함께 보고한다.
  - **S2:** 보정 기울기(실제 승패를 logit(p)에 로지스틱 회귀한 기울기)가 **0.9~1.1**
  - **S3:** 시뮬레이션 점수 차 표준편차(경기별 시뮬레이션 SD의 제곱평균제곱근)가 실제 잔차 표준편차(실제 − 시뮬레이션 평균)의 **±10% 이내**, 총점도 같은 조건
- **보고 구분:** 전체, 2025-12-21 이전(시간 단위 PDF) / 2025-12-22 이후(15분 단위 PDF), 각 구간의 그룹 A·B, 월별, 참고 행 `pre_job_start`
- **합격 시:** 픽 기능을 **기록 전용 모드**(§9.4)로 켠다.
- **불합격 시**
  1. **2025-26으로 튜닝하지 않는다.** 파라미터·구조 변경은 2024-25(개발)로만 만들고 평가한다.
  2. 픽 기능은 꺼 둔 채(확률·손익분기표만) 운영한다.
  3. 원인 분석을 보고한다(어느 기준이 왜 떨어졌는지, 구간·그룹별).
  4. 고친 모델은 **2026-27에 쌓이는 경기**로 다시 검증한다. pre_job_start를 뺀 **300경기가 쌓인 시점**에 같은 S1~S3로 판정하고, 이후 100경기마다 재확인한다.
  5. 2025-26은 다시 열지 않는다. 이미 연 결과는 참고 자료로만 남긴다.

#### 14.4.1 개봉 전 확정 사항 (2026-10-22 사용자 결정 1~8 반영)
- **개봉 때 고정하는 구성**(모두 2024-25로만 정함)
  - `data/model/params.json`(레이팅·출전 시간), `data/model/latent.json`(시뮬레이터 잠재 변수, §7.2)
  - `data/model/calibration.json`: 앙상블 가중치와 보정층
  - **사전 등록 커밋: `d40947ddbc5e50ec25e5fe28f55e9db8ca139727`** (2026-10-22 17:39 UTC, `data/model/preregistration.json`)
    - 파일 sha256: params `c3d58580…`, latent `9ca1406e…`, calibration `a6431a97…`

    - 사용자 검토에서 바뀌는 것이 있으면 다시 등록하고 이 줄을 고친다.
- **앙상블(결정 4):** 점수 차 위치 = w·(시뮬레이션 평균) + (1 − w)·(단순 기준모델)
  - w는 1개이고 0.05 간격 21개 후보 중 2024-25 Brier 최소로 정한다.
  - 시뮬레이션 분포 전체를 이 위치로 옮긴다. 시나리오는 §8.4대로 변화량을 그 위에 더한다.
- **보정층(결정 2):** 2024-25 **B판**(경기 전 스냅샷) 시뮬레이션으로 적합한다(`engine/calibrate.js`). 판정 대상과 같은 정보 조건이다(누출 점검 F8: A판 출전자 명단에는 결과 정보가 조금 섞인다).
  - 점수 차: 누적분포 P(점수 차 > t), t = −15.5~−1.5, 0, 1.5~15.5에서 보정한다. 매개변수 8개다.
    - 절편은 t에 따라 구간 선형(마디 −15.5, −5.5, 0, 5.5, 15.5)이다.
    - 기울기는 |t|에 따라 구간 선형(마디 0, 5.5, 15.5)이다.
    - 경기마다 단조 감소로 맞춘다.
  - 총점: P(총점 > L), L = 예상 ±15 범위의 x.5 기준점. 매개변수 2개(절편·기울기)다. 처음 둔 "기준점 − 예상" 항은 2024-25 적합에서 시뮬레이션 분포 항과 공선성이 생겨 그 계수를 음수로 만들었다. 그래서 리허설·시험 결과를 보기 전에 뺐다.
  - 승패·승5패·핸디캡·언더오버 확률은 모두 이 두 분포에서 읽는다. 범위 밖 기준점(|핸디캡| > 15.5, 예상 총점에서 15점 넘게 떨어진 기준점)은 픽을 내지 않는다.
- **S1~S3 정의 보완**
  - S1: 모델 확률 = 앙상블 위치로 옮기고 보정한 P(홈 승). **비교 대상은 앙상블 구성요소가 아니라 단순 기준모델이다**(팀 순레이팅 + 홈, 설계 기본값, σ는 2024-25 고정값).
  - S2: 그 승패 확률의 보정 기울기 0.9~1.1(그대로)
  - S3: 점수 차 잔차는 앙상블 위치 기준, 총점 잔차는 시뮬레이션 평균 기준이다.
- **시장별 S2와 픽 대상(결정 2)**
  - 시장별 기울기(실제 결과를 logit(보정 확률)에 회귀, 묶어서 계산)
    - 승패: 홈 승
    - 승5패: 세 결과를 묶어서
    - 핸디캡: 앙상블 예상 점수 차 ±8.5점 안의 기준점 t에서 P(점수 차 > t)
    - 언더오버: 예상 총점 ±8.5점 안의 기준점
  - 등급(통과·조건부·미달)과 조치는 아래 "판정 규칙과 결과별 조치"를 따른다.
- **판정 규칙과 결과별 조치(2026-10-22 사용자 결정 2·3, 개봉 전 확정)**
  - 근거: 약 1,100경기에서 기울기 표준오차가 약 0.09다(표본 잡음). 리허설 결과를 보고 기준을 느슨하게 한 것이 아니다.
  - 부트스트랩: 경기 단위 재표본 1,000회, 시드 1. 모든 구간은 95%다.
  - **S1(전체 관문)**
    - 보정 후 앙상블 승패 확률의 Brier가 단순 기준모델보다 **점추정으로 낮으면 통과**, 같거나 높으면 미달이다.
    - 점추정과 95% 구간(짝지은 부트스트랩)을 함께 보고한다.
    - 구간이 0을 포함하면 통과라도 **"우위 미확정"**으로 표기한다(보고서·대시보드·리포트).
  - **S3(전체 관문)**
    - 점수 차와 총점 SD 비율의 점추정이 **둘 다 0.9~1.1이면 통과**, 아니면 미달이다.
    - 비율의 95% 구간도 함께 보고한다.
  - **S2(시장별: 승패, 승5패, 핸디캡, 언더오버 각각)**

| 등급 | 조건 | 조치 |
|---|---|---|
| 통과 | 기울기 점추정 0.9~1.1 | 픽 대상(기록 전용 기간 규칙 §9.4 적용) |
| 조건부 | 점추정 0.8~1.2이면서 95% 구간이 1.0을 포함 | 기록 전용. 기록 전용 기간에 계속 추적하고 2026-27 누적 경기로 재확인한 뒤에만 픽 대상으로 올린다 |
| 미달 | 그 밖 | 기록 전용 |

      - 미달 시장은 기록 전용이다. 원인을 분석하고, 고치려면 2024-25(개발)로만 바꾼다.
      - 승패·언더오버가 먼저 통과해도 된다.
    - **S1 미달 또는 S3 미달**
      - 모든 시장이 기록 전용이다. 확률·손익분기표만 운영한다.
      - 원인 분석을 보고한다(어느 기준이, 어느 구간·그룹·시장에서).
    - **어느 경우든, 미달·조건부 항목에 대해 2025-26으로는 어떤 튜닝도 하지 않는다.**

      - pre_job_start를 뺀 300경기에서 같은 S1~S3·시장별 규칙으로 판정하고, 이후 100경기마다 재확인한다.
      - 2025-26은 다시 열지 않는다.
- **보수 확률(결정 3):** `p_cons = p − 0.1·|p − 0.5|`. 기존 공식 값도 기록한다(§9.2).
- **추가 보고(요청 7):** 결장 변수 큰 경기와 그렇지 않은 경기를 나눠 단순 기준모델 대비 성적을 보인다.
  - 기준: (B) 스냅샷에서 어느 한 팀이라도 상위 3명 중 1명 이상이 Out 또는 Doubtful
  - 상위 3명은 부상 반영 전 예상 출전 시간 기준이다.

  - 지난 시즌 데이터가 없으므로 첫 한 달은 따로 보인다.
  - 2023-24는 2024-25 튜닝의 지난 시즌 사전값으로 쓰였으므로 완전한 독립 표본은 아니다.
- **재리허설(2026-10-22 사용자 결정 1)**

  - 재리허설에서도 승패 S2가 **미달**이면, 보정층을 2023-24 + 2024-25 합산(B판)으로 **한 번만** 다시 맞추고 다시 등록한다. 개봉 전 추가 반복은 이 한 번으로 끝낸다.

## 16. 리스크와 한계
