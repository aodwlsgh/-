## 1. 커밋 가드 수정(fd02b7c)
### 바뀐 것 (`jobs/lib/commit-guard.js` +15 −3, 테스트 +18)
- `ensureRegistered(git)`를 추가했다.
  1. `git cat-file -e 53c88f5^{commit}`로 등록 커밋이 클론에 있는지 본다.
  2. 없으면 `git fetch -q --unshallow origin main`을 한 번 실행하고 다시 본다.
- `check()`는 맨 앞에서 `ensureRegistered`를 부른다.
  - 그래도 없으면 `{ ok: false, missing: 'registered commit 53c88f5 not found after fetching the history' }`를 돌려준다.
  - 이때 `git diff`·`add`·`commit`·`push`는 하나도 실행하지 않는다.
- `commitAndPush()`
  - `missing`이면 `{ ok: false, reason }`을 돌려준다. `commit-daily.js`는 이 JSON을 출력하고 exit 1로 끝난다.
  - 지시문 7단계가 이 결과를 `mark git`으로 실행 기록에 남긴다.
  - 푸시 재시도 중 다시 검사할 때도 같은 사유를 낸다.

### 53c88f5 확인이 약해지지 않은 근거
- 비교 명령은 그대로다. `git diff --name-status 53c88f5 -- <FROZEN>`(작업 트리)와 `git diff --name-status 53c88f5 HEAD -- <FROZEN>`(커밋)이다. `FROZEN` 목록, 추가(A)만 허용하는 판정, 거부 사유도 바뀌지 않았다.
- 수정 전에 53c88f5가 없으면 `git diff`가 예외를 던져 프로세스가 죽었다(JSON 결과 없음). 수정 후에는 이력을 받은 뒤 같은 비교를 하고, 그래도 없으면 커밋하지 않는다. 비교를 건너뛰는 길은 없다.
- 짧은 해시가 모호하거나 찾을 수 없으면 `cat-file`이 실패한다. 그러면 커밋하지 않는 쪽으로 끝난다.

### 원격과 명령
- 원격은 `origin`이고, 받는 것은 `main`이다. 쓰는 명령은 `fetch --unshallow` 하나다.
  - push·rebase·reset·checkout은 이 경로에 없다.
  - 모든 git 인자는 기존 `assertNoForce`를 거친다.
- 받기가 실패하면(네트워크 오류, 이미 완전한 클론) 예외를 삼키고 다시 확인한다. 그래도 없으면 위 `missing` 사유로 끝나고 커밋하지 않는다.
- 테스트(`test/p9-guard.test.js`)
  - shallow: 받은 뒤 diff 전에 fetch 순서로 커밋한다.
  - 완전한 클론: `--unshallow`를 부르지 않는다.
  - 받아도 없음: diff·commit·push 0회.
- 실제 `--depth 1` 클론으로도 확인했다. 받은 뒤 shallow가 풀렸고 동결 차이는 0이었다.

## 2. 저장된 head 파일에 version이 없어 `--head-version`으로 넘긴 횟수
- `ArtifactData get`은 문서 본문만 파일에 저장한다. version은 도구 출력 문장에만 나온다.
- `picklog.js plan`은 head가 있는데 version을 모르면 `head version unknown`(exit 4)으로 멈춘다. 지시문 3-b는 이때 get 결과의 version을 `--head-version`으로 넘기게 한다.

|---|---|---|---|

| 10-27 A | 있음 | 2 | 2, 3 |

- head 문서가 생긴 뒤의 실행 3회는 모두 첫 `plan`이 exit 4로 멈췄다. 그 뒤 `--head-version`으로 다시 해서 성공했다. 실패나 잘못된 쓰기는 없었다.
