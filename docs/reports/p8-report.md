## 3. 승인 조건별 확인
1. Playwright: `tools/browser/package.json`에 `playwright-core` 1.56.1 고정, `package-lock.json` 커밋. 루트 `package.json`·`engine/` 기존 파일은 그대로다.
2. 예시 화면
   - 2024-25 하루: 2025-02-12, 15경기, 실행 B 4경기. 고른 규칙은 2025-01~03 중 경기가 가장 많고, 17:50 ET 전 경기와 제외 경기가 없고, 실행 B 경기가 있는 날이다.
   - "예시 — 2024-25 과거 경기, 운영 데이터 아님, 보정 구간 표본 내 예측"을 크게(20px 이상, 테스트) 표시한다.
   - 픽·EV 칸 3곳과 승률·손익분기 칸에 "예시"를 붙인다. 배당 입력·픽 기록·구매 기록을 막는다.
   - 2025-26 데이터는 읽지 않는다. 형식 검사가 예시 날짜의 시즌이 2024-25인지 확인한다.
   - 실제 베트맨 배당이 없어서 예시에는 EV를 만들지 않았다(지어내지 않음).
3. 실제 DB에 시험 레코드를 쓰지 않았다. 쓰기 경로는 가짜 DB로만 시험했다(Node 12개, 브라우저 5개).
4. 동시 쓰기: 가짜 DB 테스트로 확인했다.
   - 잠금이 살아 있으면 일일 작업이 기다리고, 만료되면 무시하고 쓴다.
   - 버전 충돌이 나면 다시 읽고 재시도한다(2회째 성공, 레코드 손실 없음).
   - 재시도가 바닥나면 아무것도 쓰지 않는다.
   - 체인에 이어지지 않는 블록은 덮어쓰지 않고 두 쪽 다 멈춘다.
   - 중단된 블록은 체인에 정확히 이어질 때만 받아들인다.
   - 다른 탭이 잠금을 쥐고 있으면 쓰지 않는다.
   - 잠금이 끝나기 전에 쓸 수 없으면 멈춘다.
5. 빈 체인은 "정상(레코드 0개)"으로 표시한다. 첫 레코드는 `seq = 0`, `prevHash = null`로 설계 §12에 고정했다.
6. P9 완료 기준을 코드 완료와 사후 점검(2026-11-02)으로 나눴다(계획 P9 절). 사후 점검은 다음 단계를 막지 않는다.
7. 시간 기준은 위 표대로 통과했다.
8. 표시 규칙(브라우저 테스트)
   - 모든 픽 행과 EV 칸에 "기록 전용 — 구매 비권장"이 있다.
   - 시나리오는 "미검증", 백투백을 바꾸면 "근사"가 붙는다.
   - 시나리오를 돌려도 배당·픽 탭 내용이 그대로다.
   - 금지 문구(해제 가능·구매 가능·추천 등)는 예시·운영 두 상태의 다섯 탭 어디에도 없다.
   - 수정·삭제 컨트롤이 없다.
   - 한글 팀명에는 "미확인", 정수 기준선에는 "미지원(픽 제외)"이 붙는다.
   - 변조된 체인은 빨간 경고를 띄우고 기록을 멈춘다.
   - 소유자가 아니면 읽기만 할 수 있다.
   - 휴대폰 폭(400px)에서 가로 스크롤이 없다.
9. 회귀 테스트는 통과했다.
10. `docs/STATUS.md`를 갱신했다.

## 4. 한계와 확인하지 못한 것
- **실제 DB 쓰기 경로는 아직 실행된 적이 없다.** 가짜 DB가 문서화된 동작(마지막 쓰기 우선, `acquire` 임대, ArtifactData 일괄 쓰기의 `if_version`)을 흉내 낸 것이다. 첫 실제 쓰기(P9 첫 실행 또는 첫 배당 입력) 뒤에 체인 검증 표시와 `ArtifactData list`로 확인해야 한다.
- 접근 규칙(쓰기 owner)을 낮은 권한으로 시험하지 않았다. 시험하려면 쓰기를 시도해야 하는데, 규칙이 잘못돼 있으면 실제 레코드가 생기기 때문이다.
- 확정 시각은 쓰는 쪽 시계로 찍는다. DB가 서버 시각을 주지 않기 때문이다. 사후 변경은 해시 체인과 P9 일일 git 커밋으로 검출한다.
- 글꼴(Google Fonts)은 시험 환경에서 막혀 있어서 대체 글꼴로 시험했다. 실제 화면에서는 불러온다.
- 브라우저 시간은 이 클라우드 환경의 headless Chromium 기준이다. 사용자 PC에서는 다를 수 있다.
