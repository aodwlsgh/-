## 4. 입력 시각표 (결정 3·4)
- 새 시각표를 STATUS에 적었다.
  - 입력 창은 22:00 KST 이후 ~ 다음 날 07:30 전이다. A 그룹은 A가, B 그룹은 B가 평가한다.

- 대시보드·일일 리포트 반영은 코드라서 병합 한 건이 필요하다. 그래서 아래 표시 계획에 넣었다.

### 표시 계획 (구현 전 보고, 승인 전 구현하지 않음)
| 항목 | 위치 | 내용 |
|---|---|---|
| 입력 시각표 문구 | 대시보드 확정 화면 머리, 일일 리포트 "배당 입력" 줄 | 위 시각표 그대로 |
| 이 입력을 평가할 실행 | 확정 화면 마켓 표의 새 열 | `A (07:50 KST)` / `B (10:50 KST)` / `없음 — 사유` |
| 입력→마감 간격 분포 | 일일 리포트 모니터링(기존 "입력→평가 간격" 옆) | 경로별 n, 중앙값, 90%, 최소, 최대 |
| 시장 Brier 주의 | 해제 조건 표 "시장 대비 Brier" 행 설명 | "이른 배당일수록 시장 확률이 덜 정확해 비교가 시장에 불리함. 입력→마감 중앙값 N분" |
| 8주 진행 | 해제 조건 표 | "첫 픽 이후 경과 주, 단일 픽 수"와 참고용 "첫 평가 레코드 이후 경과 주" |

- "평가할 실행" 판정
  - 마켓의 경로를 먼저 본다(`evalPath`). C 경로면 "없음 — C 경로(입력 안 함)"이다.
  - AB 경로면 그 경기 그룹의 실행(A 그룹 → A, B 그룹 → B)을 본다.
    - 그 실행의 예약 시각이 지금보다 뒤이고, 마감이 그 시각 + 여유 2분보다 뒤면 그 실행이다.
    - 아니면 "없음 — 그 실행이 이미 지남" 또는 "없음 — 마감이 실행보다 이름"이다.
  - 계산은 예약 시각 기준이다. 실제 시작은 1~2분 늦으므로 마감이 아주 빠듯한 마켓은 표시와 달라질 수 있다고 함께 적는다.
  - "없음"인 마켓이 있으면 확정 단추 위에 개수를 경고로 보인다. 입력을 막지는 않는다.
- 병합 시점: 11-16 표시 병합은 승인된 두 가지(오래된 게시 배너, 평가 0건·마지막 배당 입력 날짜)만 한다.
  - 위 표의 다섯 가지는 승인을 받으면 ESPN 다음 날 한 건으로 병합하는 안이다.
