## 2. 승인 조건별 확인
1. **마감 전 가장 최근 입력으로 한 번만 확정한다.**
   - 대기 배당은 평가할 때 마감 전 마지막 입력을 쓴다.
   - 확정한 마켓이나 `unevaluated`로 닫은 마켓은 다시 평가하지 않는다(테스트).
2. **(가) 검증 규칙을 그대로 쓴다.**
   - B그룹은 실행 B 예측만 쓴다.
   - 마감을 넘긴 마켓은 `unevaluated` 레코드로 남긴다. 사유는 `deadline before final prediction`, `no final prediction`, `not written before deadline` 중 하나다.
   - 리포트에 오늘 수와 누적 수를 사유별로 싣는다.
   - 실행 시각(17:50/20:50 ET)은 그대로다.
3. **일일 커밋 가드**
   - 허용 경로 11개를 `docs/daily-run.md`에 적었고, 코드 목록과 같은지 테스트한다.
   - 커밋 전에 53c88f5 동결 파일 일치를 확인한다.
   - `main`에 fast-forward로만 푸시한다. 강제 푸시 인자는 코드가 거부한다.
   - **`main`에는 GitHub 브랜치 보호가 없다**(`protected: false`). 강제 푸시를 설정으로 막으려면 사용자가 설정해야 한다(4절).
4. **오버라운드 경고**
   - 1.00 미만 또는 1.30 초과면 경고만 하고 저장한다.
   - 기준값은 고정(`Object.freeze`)했고 테스트로 확인한다.
   - 첫 캡처의 2지선다 마켓은 1.11~1.15로 기준 안이었다.
5. **부상 입력**
   - 픽·EV는 PDF만 쓴 예측으로 낸다.
   - ESPN+PDF 예측은 `parallel`에 따로 기록하고 "픽·EV 미사용"으로 표시한다. 차이 나는 선수와 경기를 함께 표시한다.
   - 실시간 시험 실행(2026-10-23, 11경기)에서는 두 입력의 차이가 0경기였다.
6. **예약 작업 프롬프트**
   - "코드·파라미터·동결 경로 변경 금지", "허용 경로만 커밋"을 넣었다(테스트).
   - 승인 모드는 **auto**(`PERMISSION_MODE_AUTO`)였다. 승인 대기로 멈추지 않았다(권한 거부 0건).
7. **첫 수동 실행**
   - 빈 체인이면 `plan`이 아무 레코드도 만들지 않는다(테스트).
   - 실제로는 0단계에서 막혀 runs도 쓰지 못했다.
   - DB 확인: `meta`·`blocks`·`runs` 모두 0개.
8. **평가 못 한 마켓**
   - `unevaluated` 레코드로 체인에 남는다.
   - 대시보드 기록 탭과 리포트에 사유와 함께 표시한다.
9. **첫 실제 캡처(2026-10-23 17:00 KST)**

## 4. 막힌 것과 결정할 것
1. **예약 작업 세션에 저장소가 붙지 않는다.**
   - 이 세션에서 만든 예약 작업은 저장소를 붙이지 못한다(`sources: []`). 세션의 저장소는 시작할 때 정해진다.
   - 해결 방법은 둘이다.
     - (가) claude.ai의 예약 작업(루틴) 화면에서 저장소 `aodwlsgh/-`를 선택해 두 작업을 만든다. cron과 프롬프트는 `docs/daily-run.md`에 있다. 실행마다 새 세션이 뜨는 승인된 방식 그대로다.
     - (나) 저장소가 붙은 실행 전용 세션을 하나 만들고, 예약 작업이 매번 그 세션을 깨운다. 사용자 조작은 필요 없지만, 대화가 한 세션에 계속 쌓이므로 "실행마다 새 세션"이라는 승인 내용이 바뀐다.
   - (가)로 만든 뒤 수동 실행으로 확인하면, 무인 git 푸시·DB 쓰기·재게시를 보고하겠다.
2. **`main` 브랜치 보호:** 지금은 없다. 강제 푸시를 설정으로 막으려면 GitHub Settings → Branches(또는 Rules)에서 `main`에 "강제 푸시 금지" 규칙을 켜야 한다. "PR 필수" 규칙은 일일 푸시를 막으므로 켜지 않는다.
3. **베트맨 마감 시각**(첫 캡처 관찰)
   - 08:00 KST 이전 시작 경기는 전날 23:00 KST에 마감된다. 실행 A보다 먼저다.
   - 2024-25 일정 기준으로 10.6%(130경기)는 평가할 수 없다. 5.5%(68경기)는 규칙 미확인이다. 서머타임 기간에 몰려 있다.
   - 실행 시각을 앞당기는 것은 검증 경로가 바뀌므로 지금은 하지 않았다.
4. **"조합"만 있는 경기:** 화면상 단일 구매가 안 되는 것으로 보인다(05:00~10:30 경기, 11:00 경기만 "조합·한경기"). 단일 픽 집계는 그대로 두었다. 확인이 필요하다.
5. **첫 캡처 배당의 기록 여부:** 회차 번호가 없어 기록하지 않았다. 기록하려면 회차와 함께 지시해 달라. 대시보드에서 직접 입력해도 된다.
   - 08:00 KST 경기들은 오늘 23:00 KST가 마감이다. 실행 A 전이므로 기록해도 "평가 못 함"이 된다.
