# 이른 실행(C) 검증 계획 — 초안, 승인 전 구현 없음

- 작성: 2026-10-27 (사용자 "1 진행, 2 계획 작성")
- 상태: **검증 합격(2024-25만으로 판정), 구현 승인(2026-10-27 "C 검증 검토 / 구현 승인" 1~12), 구현됨. 서머타임은 안 "다" 승인(2026-10-28), 07:50 ET 재검증 합격(8절, 1회 계산), 기준 시각 전환 구현(10-31까지 08:50 ET, 11-01 경기일부터 07:50 ET).** 검증(3절) 승인됨(2026-10-27 사용자 "추천대로"). 구현(4절)은 검증 결과 보고와 사용자 승인 뒤에만 한다. 합격 기준은 결과를 보기 전에 아래로 고정했다.

## 1. 문제
- 베트맨 마감이 전날 23:00 KST(= 당일 10:00 EDT, 11-01 뒤 09:00 EST)인 경기가 대부분이다. 관측 25경기 중 19경기(`docs/STATUS.md` 집계, `docs/betman/2026-10-2*-capture.md`).
- 최종 예측은 실행 A·B(17:50·20:50 ET = 06:50·09:50 KST)에 나온다. 마감이 그보다 먼저인 경기는 평가할 수 없다("평가 못 함 — 최종 예측보다 베트맨 마감이 먼저").
- 그래서 지금 설계로는 평일 경기를 거의 평가하지 못한다.

## 2. 제안
- **실행 C:** 매일 21:50 KST에 한 번 더 돈다. 서머타임 중에는 08:50 EDT, 11-01 뒤에는 07:50 EST다. 마감(23:00 KST)도 KST로 고정이라, C는 서머타임 때 시각을 바꿀 필요가 없다.
- 입력: C 시각까지 읽을 수 있는 가장 최근 NBA 부상 리포트(제목 시각과 Last-Modified 중 늦은 쪽). 기존 스냅숏 규칙(`engine/snapshot.js availableAt`)을 그대로 쓴다. ESPN은 지금처럼 병행 기록만 한다.
- 모델, 파라미터, 보정, 앙상블 가중치는 그대로 쓴다. 다시 맞추지 않는다.
- **어떤 예측이 평가에 쓰이나**
  - 마감이 실행 A·B보다 먼저인 경기는 C의 예측을 "평가용 최종(아침 리포트)"으로 쓴다. 대시보드와 장부에 C라고 따로 표시한다.
  - 마감이 시작 시각인 경기는 지금처럼 A·B의 최종 예측을 쓴다. 검증된 경로가 그대로 남는다.
  - 마감 시각은 배당 입력의 `deadline`으로 경기마다 이미 알고 있다. 판단은 입력 시점에 자동으로 한다.
- 기록 전용은 그대로다. 2026-27 첫 한 달은 시장과 관계없이 기록 전용이고, 해제는 사용자 승인으로만 한다(설계 §9.4).

## 3. 검증 (구현 전에 먼저 한다)
1. **데이터 확인 (반나절)**
   - 2024-25 정규 시즌 경기일마다 C 시각(현지 08:50 ET) 이전의 리포트를 NBA 서버에서 받는다.
   - 2026-10-27 표본 3일(11-12, 01-15, 03-20)에는 06·07·08·09·11AM, 01PM 파일이 모두 있었다(HTTP 200).
   - 경기일 중 C 시각에 쓸 수 있는 리포트가 있는 비율을 센다. **95% 미만이면 멈추고 보고한다.**
2. **다시 계산 (1일)**
   - 2024-25 B판 워크포워드(등록 경로 그대로)를 C 스냅숏으로 다시 돌린다.
   - 같은 경기에서 지금 기준(17:50·20:50 ET)의 예측과 나란히 비교한다.
   - 2023-24(리허설 시즌)도 같은 방식으로 돌려 보조 근거로 쓴다.
   - **2025-26은 쓰지 않는다**(2026-10-23에 한 번 열었음, 다시 열지 않음).
3. **비교 지표:** 승패 Brier·로그 손실, 마진 MAE, 총점 MAE, 승패 보정 기울기, 지금 기준 대비 차이와 그 부트스트랩 95% 구간.
4. **합격 기준 (2026-10-27 고정, 결과 보기 전)**
   - 승패 Brier 증가 ≤ 0.001 (확률 오차로 약 3%p, 픽 기준 EV +3%와 같은 크기. 처음 제안 0.005는 약 7%p라 느슨해서 고침)
   - 승패 로그 손실 증가 ≤ 0.003
   - 마진 MAE 증가 ≤ 0.3점, 총점 MAE 증가 ≤ 0.3점
   - 보정 기울기가 지금 기준에서 ±0.10 안
   - 하나라도 넘으면 C를 쓰지 않고 결과만 보고한다.
5. **한계 (그대로 보고한다)**
   - 2024-25는 보정을 맞춘 시즌이라 표본 안 비교다. 처음 보는 시즌 검증이 아니다.
   - 아침 리포트에 없는 늦은 결장(경기 당일 오후 발표)은 C 예측에 빠진다. 위 비교가 그 손실을 잰다.

## 7. 서머타임(2026-11-01) 계획 — 승인 전 구현 없음 (2026-10-27 승인 조건 4·9)
- **사실**
  - 예약 작업은 KST 고정이다. 21:50 KST는 11-01 전에는 08:50 EDT, 11-01부터는 07:50 EST다.
  - 마감도 KST(전날 23:00)로 관측됐다. 11-01 전에는 10:00 EDT, 뒤에는 09:00 EST다.
  - 검증은 08:50 ET 기준(2024-25에서는 모두 08:30 AM 리포트)으로 했다.
- **11-01 뒤 21:50 KST(07:50 EST)에 C가 돌면** (지금 코드, 바꾸지 않음)
  - `searchAt = now < 08:50 ET ? now : 08:50 ET`이므로 07:50 EST까지 읽을 수 있는 가장 최근 리포트를 쓴다. 2026-27은 15분 간격이라 대개 07:30·07:45판이다.
  - `isFinalRun('C')`는 08:50 ET 전이라 거짓이다. 그래서 예측은 "예비"로 게시되고, C 경로 마켓은 평가하지 않는다(배당만 기록 → 마감 뒤 "평가 못 함").
  - 오류로 막지는 않는다. 그날 C는 사실상 평가를 하지 않는다.
- **11-01 뒤 시각 후보** (마감 09:00 EST = 23:00 KST 기준 여유)

  | 안 | C 실행(KST) | ET | C 기준 시각 | 마감까지 | 검증 | 판단 |
  |---|---|---|---|---|---|---|
  | 가 | 22:50 | 08:50 EST | 08:50 ET(지금) | 10분 | 검증 그대로 | 실행 3~4분, 게시, 캡처·확정이 10분 안에 끝나지 않는다. 쓸 수 없다 |
  | 나 | 22:40 | 08:40 EST | 08:40 ET로 변경 | 20분 | 2024-25 스냅숏이 모두 08:30판(가용 08:30)이라 08:40 기준에서도 같은 리포트다. 같은 파일임을 확인하는 계산만 필요(새 열람 아님) | 빠듯하다. 사용자가 미리 캡처해 두면 가능 |
  | 다 | 21:50(그대로) | 07:50 EST | 07:50 ET로 변경 | 70분 | 2024-25를 07:50 ET 스냅숏(07:30판)으로 다시 계산해 같은 기준으로 판정해야 한다(2024-25 추가 계산) | 여유가 가장 크다. 검증이 다시 필요하다 |
  | 라 | — | — | — | — | — | 11-01부터 C를 멈추고 A·B만 쓴다. 평일 경기 평가는 다시 거의 없어진다 |
- **추천: 다.** 마감 여유 70분은 지금과 같다. 재검증은 같은 스크립트로 1시간 안에 끝난다. 불합격이면 나, 그것도 안 되면 라로 간다.
  - 다를 고르면 C 기준 시각을 계절과 관계없이 07:50 ET로 바꾼다. 11-01 전(08:50 EDT 실행)에도 07:50 ET까지의 리포트를 쓴다. 이렇게 해야 검증한 기준과 실제 실행이 같다.
- **11-01 예약 시각 처리**
  - 다·라: C 예약 시각은 바꾸지 않는다(라는 사용자가 C 작업을 끈다).
  - 나: 11-01 09:50 KST 실행 뒤부터 11-02 21:50 KST 전까지, 사용자가 A·B를 바꿀 때 C도 21:50 → 22:40 KST로 함께 바꾼다.
  - 11-01 21:50 KST(11-01 ET 경기의 C)는 이미 07:50 EST다. 다·나가 구현되기 전이면 그날 C는 예비가 된다.

## 8. 07:50 ET 재검증 (안 "다", 2026-10-28 사용자 승인) — 합격 기준, 계산 전 고정
- **승인 조건**(2026-10-28 "C 구현 승인 / 11-01 안 다 승인" 2)
  - 기준은 계산 전에 이 절로 등록한다. 등록 커밋의 해시와 시각을 보고한다.
  - 2024-25만 쓴다. 2023-24와 2025-26은 읽지 않는다. 재검증 횟수는 `docs/reports/season-reads.json`에 남긴다.
  - 지표를 계산하기 전에 리포트 판 분포와 아침 판이 없는 경기 비율을 먼저 보고한다.
  - 불합격이거나 확보율이 모자라면 안 "라"(11-01부터 C 중단)로 간다. 안 "나"(22:40)는 쓰지 않는다.
  - 결과는 11-01 21:50 KST 전에 보고한다.
  - 합격 전까지 C는 지금 기준(08:50 ET)을 그대로 쓴다. 기준 시각은 합격 뒤에 바꾼다.
- **스냅숏 규칙**(운영 코드와 같다)
  - 경기일 07:50 ET를 기준으로 `liveInputs`와 같은 규칙으로 고른다.
  - 15분 간격으로 4시간(16단계)을 거슬러 찾는다. 2025-12-22 전에는 정시 파일만 있다.
  - 가용 시각은 제목 시각과 Last-Modified 중 늦은 쪽이다.
- **합격 기준**(eb471ed와 같은 허용선, 완화 없음)
  - **아침 리포트 확보율 ≥ 95%.** 분모는 2024-25 정규 시즌 전체 경기, 분자는 아래 조건을 모두 갖춘 경기다.
    - 경기일(ET) 날짜의 리포트다.
    - 07:50 ET까지 가용하다.
    - 형식 오류가 없다.
  - 아래 차이는 모두 07:50 ET판 − 등록 예측(17:50·20:50 ET)이고, 판정 대상 경기의 점추정으로 판정한다.

    | 지표 | 허용선 |
    |---|---|
    | 승패 Brier | ≤ +0.001 |
    | 승패 로그 손실 | ≤ +0.003 |
    | 마진 MAE | ≤ +0.3점 |
    | 총점 MAE | ≤ +0.3점 |
    | 승패 보정 기울기 차이 | ±0.10 안 |
  - 하나라도 넘으면 불합격이다.
  - 95% 구간과 단순 기준모델 대비 Brier 차이는 참고로만 싣는다.
